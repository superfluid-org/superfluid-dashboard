01 · Executive verdict

Keep the integration. Improve the operating model.

Alchemy remains the best near-term choice because the adapter is already live, the enriched response matches the table, and the free/PAYG economics are unusually forgiving. The strongest reason to switch would be better token safety—not price.

Recommendation · Stay on Alchemy

Use Alchemy as the portfolio indexer; keep Superfluid data authoritative.

Merge priced ERC-20 holdings from the Portfolio API with protocol-native Super Token data exactly as the dashboard does today. Add short server-side caching and request coalescing before considering a provider migration. Revisit Moralis if scam/spam protection becomes a product requirement, or Ankr if raw cost becomes the sole driver. Run OKX and Mobula against the same wallet corpus before making that decision—their published balance APIs are stronger than the original shortlist reflected.

A token list is not a balance API. Uniswap-style token lists curate known contract metadata; they do not discover everything a wallet owns or calculate balances. They are useful as a trust signal and logo fallback, not as the portfolio data source.

Found, but not shortlisted

Dune Sim API: an excellent technical fit, but Alchemy’s migration notice states that Sim shut down on 01 August 2026. Do not start a new integration.

Allium: strong real-time wallet infrastructure, but its public machine-payment balance call is $0.03 and price enrichment is a separate product path.

Zapper API: relevant DeFi balance coverage, but current self-service documentation and pricing are fragmented; treat it as a sales-led option.

Coinbase Prime / CDP: useful for wallets managed inside Coinbase products, not arbitrary external-address discovery for this dashboard.

06 · Dashboard fit

A durable data path for one combined table.

Treat the external service as discovery and enrichment. Superfluid’s own sources should continue to define Super Token semantics and live protocol state.

01 / INPUT

Connected wallet + active network set

Normalize the address and send the selected chain IDs to the server route.

02 / DISCOVERY

Alchemy Portfolio API

Fetch non-zero ERC-20 balances with metadata and USD price; exhaust pages safely.

03 / AUTHORITY

Superfluid protocol data

Fetch Super Token snapshots separately so streamed balances remain precise.

04 / VIEW MODEL

One portfolio table

Deduplicate, label token type, sort by network and value, then render together.

Do next

Add a 30–60 second server cache.

Key by normalized wallet + sorted network set. Coalesce simultaneous requests to stop duplicate CU spend during rerenders and tab activity.

Measure

Log pages, tokens and CU estimates.

Record page count and response time without addresses. The long tail of spam-heavy wallets—not average users—will determine real cost.

Challenger test

Benchmark OKX and Mobula now.

Replay 50 representative wallets, scoring missing prices, risk-token false positives, latency, pagination and exact Superfluid-chain coverage before deepening the Alchemy dependency.

✓

The current adapter already makes several sound choices: the Alchemy key stays server-side; duplicate tokens are collapsed; unpriced dust is excluded unless it appears in the maintained Super Token list; unsupported chains fall back to direct balance reads; and the UI merges ERC-20 rows into the existing per-network tables.

Method

Research was limited to official product pages, API references, and public pricing pages checked on 06 August 2026. Scores are editorial and weighted toward the Superfluid Dashboard’s current needs: enriched ERC-20 discovery, multi-chain efficiency, safe rendering, predictable pricing, and implementation effort.

  • Cost models assume one first page unless noted.
  • Alchemy’s dashboard estimate is based on the current five-network chunks and 10 mapped mainnets.
  • Annual-billing prices are labeled; taxes and negotiated discounts are excluded.
  • Feature claims are based on documented schemas, not vendor marketing alone.
  • The primary table contains fully modeled routes; the extended field is a qualification screen, not a normalized quote.
